# Server-seed table islands: dehydrated state into a `HydrationBoundary`

Issue #44 (found in the two-axis review of #42). frontend-architecture's table rule promised islands "seeded with server `initialData`"; the categories surface never did it, so a first visit paid the full shell → hydrate → XHR → "Loading…" waterfall. Gated before #6 so the pattern is designed once. Three shapes were compared: **P1 server-seed** (this ADR), P2 client-fetch + a prettier skeleton (rejected: keeps the waterfall, fails the AC, downgrades four written docs), P3 server-read-only rows with `router.refresh()` on mutation (rejected: rewrites ADR 0019's query-key/invalidation model and makes refetch-after-create untestable in jsdom).

**Mechanism: `dehydrate` + `HydrationBoundary`, not `initialData`.** Dehydrated entries are key-addressed — the query key travels inside the payload — so a seed/key mismatch degrades to a *miss*: the island fetches normally and nothing is wrong. With `initialData` passed as a prop, every island would need a hand-written `seedPage === page` guard, copy-pasted across #6/#7/#8, and the island would stop being prop-less; one wrong guard shows page-0 rows under `?page=1`. The seed and the island agree structurally because both sides go through the same factory (`features/<f>/api.ts` — the `features/<f>/api.ts` home architecture mandates; the factory had to move out of the `"use client"` panel, since a server component can't import value exports from a client module) and the same page parser: the server rebuilds `URLSearchParams` from the page's `searchParams` prop (repeated values appended, first wins in `.get`) and runs the same `toPage`, which lives in its own leaf module (`hooks/to-page.ts`, re-exported from `use-page-param` — the hook file imports `next/navigation` client hooks and cannot enter the RSC graph; `next build` proved it). Any drift between seed and island is pinned by a test: the dehydrated `queryKey` must deep-equal `factory(N).queryKey` for no-param / 0 / N / garbage / repeated `?page=`.

**Interface.** `lib/api/seed.tsx` exports the pair: `TableSeed` (the async RSC a page mounts — awaits `searchParams`, seeds, wraps the island in `<HydrationBoundary>`) and `seedTable` (the plain, jsdom-callable core it awaits; a deliberate near-homograph pair, documented as such). The credential is `sessionInit()` in `lib/api/server.ts` — the one `lib/api` server helper architecture.md §4 already promised: it forwards `SESSION_COOKIE` verbatim from `cookies()`, decodes nothing, never calls `/auth/me`, and returns `{}` rather than failing when the cookie is absent. The base URL is `apiBaseUrl()`: `NEXT_PUBLIC_API_BASE_URL` reads from `process.env` at request time on the server (Next inlines it only into the browser bundle), defaulting to `:8081` — no internal-only env var, so browser and server always name the same backend. For #6/#7/#8 the shared server surface is the **credential only**: `sessionInit()` returns the `RequestInit` each list's own fetch takes as `init?` and spreads — deliberately no generic `serverFetch(path)` wrapper, so "each list keeps its fetch" (frontend-architecture §Data fetching) survives the move server-side. The page stays **sync** (build-safe under `cacheComponents`): it hands the `searchParams` promise down, the await happens inside `TableSeed` within `<Suspense fallback={<TableSkeleton/>}>`, and `next build` reports `/categories` as a Partial Prerender — static shell, dynamic seed streamed behind it. `TableSkeleton` (`components/shared/`) is the one "rows aren't here yet" visual: the Suspense fallback *and* `<PagedList>`'s client loading state, so the degraded path looks like the seeded one.

**Query client policy.** `createQueryClient()` (exported from `providers/query-provider.tsx`) adds `staleTime: 30_000` alongside the existing `retry: false` / `refetchOnWindowFocus: false`. StaleTime is the no-double-fetch mechanism (architecture.md §8): a seed is fresh at hydration, so the island's first mount refetches nothing. Why 30s: it absorbs hydration latency and server/client clock skew; `Infinity` rots lists; `0` was exactly the forbidden extra fetch. Writes are unaffected — `invalidateQueries` overrides staleTime. `getQueryClient()` is env-branched per TanStack's documented Next pattern: **server** = new per-request client (`cache()` + the `useState` initializer — today's module singleton would receive user A's seed during SSR and could serve it into user B's HTML, since hydration only overwrites entries that are newer and a degraded seed for B never clears A's), **browser** = one module-level instance, **tests** = fresh per render (required once staleTime ≠ 0 — it also retired categories.test.tsx's "unique row names or the shared cache lies" comment). Deliberately **no `use cache` / server cache** for the seed: client-side writes can't `updateTag`, so a cached seed would serve pre-mutation rows; every render is a live fetch — one server→`:8081` GET per route render, the same count as today, just moved one hop. Sidebar links stay on default prefetch (not `prefetch={true}`, which would fire seed fetches at link-viewport and pin stale seeds).

**Degradation rule.** The seed may only improve the first paint, never change the outcome: every failure (401/500/network/JSON/`cookies()` with no request scope) degrades to an empty dehydrated state, and an empty state means the island runs today's code path unchanged. `seedTable` never rejects. No seed timeout was added (an optional `AbortSignal.timeout` on the seed fetch remains open hardening — a hung backend stalls the streamed island, nothing worse).

**ADR 0018 is not amended.** 0018 governs the *user* read (`/auth/me`, client-side) and stays as written; seeding needs the **credential**, not the user. The first HTML still carries no user info, role gating still happens in `proxy.ts` plus backend re-verification, and server→`:8081` raises no CORS question (ADR 0015's `localhost:3000` grant is browser-only). This is not the banned BFF: a per-request component fetch, no route handler, no rewrite. ADR 0005 **is** amended: its `initialData` wording names the mechanism superseded here — the hybrid server/client policy it decided is unchanged (flagged per docs/agents/domain.md "Flag ADR conflicts"; 0005 carries the amendment note).

**Tests.** jsdom can't render an async RSC or call the real `cookies()`, so `__tests__/categories.test.tsx` renders `CategoriesPanel` (the island) instead of the page — all its behavior tests unchanged — and the new `__tests__/seed.test.tsx` calls `seedTable` directly with the request-scope boundary (`next/headers`) mocked: it asserts the outbound `?page=N` + `Cookie:` header, key equality with the factory, degradation to empty, and — rendering the island inside `<HydrationBoundary state>` — rows present *synchronously* with the MSW GET count unchanged (the no-double-fetch test, testing-strategy §4). Full server-path evidence (rows in the first HTML, deep links) is Playwright's (testing-strategy §5). Revisit triggers: `use cache` if seed latency ever bites (then the `updateTag` gap must be solved first), and per-list filters — when they arrive, the URL parser grows once, centrally, in `to-page.ts`.
